## Worth installing now

1. **hf-cli** (Hugging Face). It gives Claude the current command list for the `hf` command-line tool, so model search, model downloads and uploads use real flags. It helps at plan steps 3 to 6, and with the open task "check Hugging Face for newer 4B models". Source: https://github.com/huggingface/skills/blob/main/skills/hf-cli/SKILL.md
2. **huggingface-local-models** (Hugging Face). It covers llama.cpp and GGUF: how to pick a quantization level, the `convert_hf_to_gguf.py` and `llama-quantize` commands, and how to start `llama-server` and test it. This is plan step 6, and it also helps run the baseline in step 4. Source: https://github.com/huggingface/skills/blob/main/skills/huggingface-local-models/SKILL.md
3. **hf-mem** (Hugging Face). It estimates how much GPU memory a model needs without downloading it, and says whether it fits a given card. Use it at step 3 to choose a Runpod GPU for the 30B teacher, and at step 6 to check which GGUF levels fit 16 GB. Source: https://github.com/huggingface/skills/blob/main/skills/hf-mem/SKILL.md
4. **huggingface-best** (Hugging Face). It queries the Hub's official benchmark leaderboards and filters models by the memory of your device. It helps with the two open decisions: which student at step 4 and which teacher at step 3. No leaderboard measures complaint-to-JSON extraction, so treat its ranking as a shortlist. Source: https://github.com/huggingface/skills/blob/main/skills/huggingface-best/SKILL.md
5. **astral** plugin with the `uv`, `ruff` and `ty` skills (Astral, the makers of `uv`). It keeps Claude on `uv` commands for the project environment and for single-file scripts with inline dependencies. It helps from step 1 onward, each time a script or dependency is added. Source: https://github.com/astral-sh/agent-plugins/blob/main/plugins/astral/skills/uv/SKILL.md

One install path covers items 1 to 4. Install the `hf` tool, then run `hf skills add --global` for `hf-cli` and `hf skills add <name> --global` for each of the other three. The Hugging Face CLI reference says this writes the skill to `~/.agents/skills` and adds a symlink in `~/.claude/skills` (https://huggingface.co/docs/huggingface_hub/main/en/package_reference/cli, section "hf skills add"). Item 5 is two commands inside Claude Code: `/plugin marketplace add astral-sh/agent-plugins`, then `/plugin install astral@astral-sh` (https://github.com/astral-sh/agent-plugins/blob/main/README.md).

Hold **huggingface-llm-trainer** until step 5, and read the warning about it in the last section first.

## Every skill examined

"Automatic" means Claude may load the skill by itself when the description matches. "Slash only" means the frontmatter sets `disable-model-invocation: true`, which the Claude Code docs define as "Claude can't invoke the skill on its own" (https://code.claude.com/docs/en/skills, "Control who invokes a skill"). A plugin skill is called as `/plugin-name:skill-name` (same page, "Choose where skills load").

## Gaps where a custom skill would help

No existing skill was found for these needs. Each is a candidate for a small project skill in `.claude/skills/`, written with the installed `skill-creator` once the matching script exists.

- **Evaluation of the triage JSON.** Nothing found scores valid-JSON rate and per-field accuracy against teacher labels and CFPB categories. The Hugging Face evaluation skill runs public benchmarks, and the MLflow and DeepEval skills use LLM judges. A project skill should hold the exact command for the eval script, the held-out file path, the rule that the 500 held-out complaints are never trained on, and the table format for comparing baseline, fine-tuned and each GGUF level.
- **Teacher labeling on Runpod.** No skill covers batch-labeling with an open-weights model, validating each output against the schema, and retrying failures. The Runpod skills cover the pod itself. A project skill could record the prompt, the schema, the pod type and price, and the "read 50 labels by hand first" gate.
- **Unsloth fine-tuning on a local 16 GB GPU or a Runpod pod.** Unsloth publishes no Claude Code skill in its repository. The only Unsloth material inside a skill is `references/unsloth.md` in `huggingface-llm-trainer`, 313 lines whose text-model example uses an LFM2.5 model inside a Hugging Face Jobs script (only its first 110 lines were read) (https://github.com/huggingface/skills/blob/main/skills/huggingface-llm-trainer/references/unsloth.md). Unsloth's own docs at https://unsloth.ai/docs remain the source for QLoRA settings, WSL2 setup and its GGUF export.
- **CFPB data preparation.** No skill covers the CFPB CSV, filtering to complaints with a narrative, or stratified sampling by product. This is ordinary pandas work and may not need a skill, only a script and two lines in CLAUDE.md.
- **Jupyter notebooks and pandas analysis.** No first-party skill for either was found in the repositories above. Jupyter has no skills repository under the names tried (`jupyter/skills`, `jupyter-ai-contrib/jupyter-ai-skills`). Claude Code handles both without a skill.
- **Git basics for a non-engineer.** Nothing found teaches git. The installed `teach` skill can do this on request, and `git-guardrails-claude-code` is the only safety net found.
- **Experiment log.** Trackio records training curves. Nothing found keeps one table of every run (model, quantization level, valid-JSON rate, field accuracies). A CSV that the eval script appends to would do, described in the evaluation skill.

## Things to be wary of

- **huggingface-llm-trainer submits paid cloud jobs by design.** Its "Key directives" tell Claude to "ALWAYS use `hf_jobs()` MCP tool" and, when asked to train, to "create the training script AND submit the job immediately". The prerequisites say Hugging Face Jobs need a Pro, Team or Enterprise plan, and its hardware table lists roughly 0.75 to 20 US dollars per hour. This conflicts with the plan to train on the local GPU or a Runpod pod with an explicit go before spending. If you install it at step 5, tell Claude to use it for the Unsloth and GGUF references only. Source: https://github.com/huggingface/skills/blob/main/skills/huggingface-llm-trainer/SKILL.md
- **Token use.** `huggingface-best` reads `~/.cache/huggingface/token` and sends it as a bearer header to `huggingface.co`. `hf-mem`, `hf-cli` and the evaluation skill use `HF_TOKEN` for gated models. If the chosen student or teacher is a gated model, a token will be needed. Use a read-only token.
- **Skills that run downloaded code.** `hf-mem` runs `uvx hf-mem`, which fetches a package from PyPI each time. The astral plugin's language server runs `uvx ty@latest server`. The `hf-cli` skill prints an installer line, `curl -LsSf https://hf.co/cli/install.sh | bash -s`. The W&B and marimo READMEs install through `npx skills add`, a third-party installer that needs Node. Astral's own `uv` skill notes that `uvx` "can be unsafe - only run well-known tools".
- **Skills that write files.** `hf skills add` writes to `~/.agents/skills` and symlinks into `~/.claude/skills`; without `--global` it writes `.agents/skills` and `.claude/skills` into the current project folder. `git-guardrails-claude-code` writes a hook script and edits `.claude/settings.json` or `~/.claude/settings.json`. `claude-md-improver` edits CLAUDE.md after approval. `session-report` writes an HTML file into the working directory.
- **Trackio dashboards can be public.** If a `space_id` is passed, Trackio syncs metrics to a Hugging Face Space, and the skill states that auto-created Spaces are "PUBLIC by default". Leave `space_id` out to keep runs local, or pass `private=True`. Source: https://github.com/huggingface/skills/blob/main/skills/huggingface-trackio/SKILL.md
- **Automatic triggers cost context.** The Claude Code docs say skill descriptions are loaded into every session and each is cut at 1,536 characters in the listing (https://code.claude.com/docs/en/skills). Several Hugging Face descriptions are long and say "always use this skill". Installing all 25 would add noise, which is another reason to install four.
- **Model names inside skills are examples.** `huggingface-local-models` uses `unsloth/Qwen3.6-35B-A3B-GGUF` in its commands, and the trainer skill uses LFM2.5. Do not read them as recommendations for this project.
- **Pinned and moving versions.** Plugins from marketplaces update themselves. Copied folders and `hf skills add` installs do not; `hf skills update -g` refreshes the latter.
